MIGRATION PLAN (Step-by-step)

Step 1 — Remove open_filex and add compliant pickers
1. In pubspec.yaml, remove:
   - open_filex: 4.7.0
2. Ensure these are present/added:
   - image_picker: ^1.x (modern version uses Android Photo Picker on API 33+)
   - file_picker: keep (already in project) for documents only
   - Optional for sharing instead of "open": share_plus: ^10.x
3. Run:
   - flutter clean
   - flutter pub get

Step 2 — Replace OpenFilex.open(...) calls
1. For images/videos: do not "open" from storage; show inside the app or let user pick via Photo Picker.
   - Replace OpenFilex.open(downloadFilePath) with in-app viewing or share intent (see code below).
2. For documents (PDF, etc.): either
   - View inside app with a viewer (e.g., pdfx/syncfusion viewer), or
   - Share with share_plus to let the user choose an app (no broad permissions required).

Step 3 — Adopt system pickers for user selection
- Use image_picker for photos/videos.
- Use file_picker for documents only when necessary.
- Do NOT request READ_EXTERNAL_STORAGE or READ_MEDIA_*.

Step 4 — Strip forbidden permissions from manifest
- Keep your existing manifest without these permissions.
- If merged manifests still include them from transitive libs, explicitly remove via tools:node="remove" (see snippet).

Step 5 — Validate and test
- Build debug and release, verify merged manifest does not include READ_* permissions.
- Test on Android 13/14 devices/emulators.

CODE SNIPPETS

A) Dart: Pick a single image (Android 13+ uses system Photo Picker)

Dependencies:
- image_picker in pubspec.yaml

Example:
```dart
import 'package:image_picker/image_picker.dart';

final ImagePicker _picker = ImagePicker();

Future<void> pickImageOnce() async {
  final XFile? image = await _picker.pickImage(source: ImageSource.gallery);
  if (image == null) return; // user cancelled
  // Use image.path inside app (e.g., display with Image.file/FileImage)
}
```

B) Dart: Pick a single video
```dart
import 'package:image_picker/image_picker.dart';

final ImagePicker _picker = ImagePicker();

Future<void> pickVideoOnce() async {
  final XFile? video = await _picker.pickVideo(source: ImageSource.gallery);
  if (video == null) return;
  // Play video via a player plugin or in-app player
}
```

C) Dart: Pick a document with file_picker (no broad permissions)
```dart
import 'package:file_picker/file_picker.dart';

Future<void> pickDocument() async {
  final FilePickerResult? result = await FilePicker.platform.pickFiles(
    type: FileType.custom,
    allowedExtensions: ['pdf', 'doc', 'docx'],
  );
  if (result == null) return;
  final String? path = result.files.single.path; // content URI or SAF-backed path
  if (path == null) return;
  // Open inside app (preferred) or share externally (see below)
}
```

D) Dart: Replace OpenFilex.open(...) with share_plus (open-with chooser)
```dart
import 'package:share_plus/share_plus.dart';

Future<void> shareOrOpenFile(String filePath) async {
  final XFile xfile = XFile(filePath);
  await Share.shareXFiles([xfile]); // system chooser; no READ_* permission required
}
```

E) AndroidManifest.xml: Remove forbidden permissions introduced by dependencies
- Ensure manifest root includes tools namespace.
- Add removal entries only if merged manifests still include them after removing open_filex.

Snippet (android/app/src/main/AndroidManifest.xml):
```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools">

    <!-- keep your other entries -->

    <!-- Strip storage/media permissions if merged from dependencies -->
    <uses-permission android:name="android.permission.READ_EXTERNAL_STORAGE" tools:node="remove" />
    <uses-permission android:name="android.permission.READ_MEDIA_IMAGES" tools:node="remove" />
    <uses-permission android:name="android.permission.READ_MEDIA_VIDEO" tools:node="remove" />
</manifest>
```

F) Optional: Keep legacy permission only on Android <= 32
```xml
<uses-permission
    android:name="android.permission.READ_EXTERNAL_STORAGE"
    android:maxSdkVersion="32" />
```
(Use only if you absolutely need legacy behavior on Android 12L and below.)

POTENTIAL ISSUES WHEN REMOVING open_filex & REPLACEMENTS

- Issue: Cannot "open in external app" directly via OpenFilex.open(path)
  - Replacement: share_plus (Share.shareXFiles) to invoke system chooser without storage permissions
  - Alternative: Render inside app (e.g., Image.file, pdf viewers) for best UX

- Issue: Paths vs content URIs
  - Use the path/URI provided by image_picker/file_picker; they handle SAF/Photo Picker and avoid broad permissions

- Issue: Files saved to public storage
  - Prefer app-private cache via path_provider; if exporting to public, use SAF-oriented packages (e.g., file_picker saveFile, flutter_file_dialog) rather than raw File writes to shared storage
